# Руководство по интеграции Django бэкенда с React фронтендом

## Обзор

Твой проект теперь состоит из двух частей:

1. **Фронтенд** (React) - находится в папке `sakura_learn/client`
2. **Бэкенд** (Django) - находится в папке `server`

## Запуск приложения

### Шаг 1: Запуск Django бэкенда

```bash
cd sl/server
source venv/bin/activate  # На Linux/Mac
python manage.py runserver 0.0.0.0:8000
```

Бэкенд будет доступен по адресу: **http://localhost:8000**

API документация доступна по адресу: **http://localhost:8000/api**

### Шаг 2: Запуск React фронтенда (в отдельном терминале)

```bash
cd sl/sakura_learn
npm run dev
```

Фронтенд будет доступен по адресу: **http://localhost:5173** или **http://localhost:3000**

## Что было изменено

### Фронтенд (React)

#### 1. Новый API клиент (`client/src/lib/api.ts`)
- Класс `ApiClient` для взаимодействия с Django API
- Методы для регистрации, входа, выхода и управления профилем
- Автоматическая обработка ошибок и CORS

#### 2. Новый контекст авторизации (`client/src/contexts/AuthContext.tsx`)
- Управление состоянием пользователя
- Функции: `register`, `login`, `logout`
- Проверка аутентификации при загрузке приложения
- Сохранение информации о пользователе

#### 3. Обновленные страницы
- **SignUp.tsx**: Теперь отправляет данные на `/api/auth/register/`
- **SignIn.tsx**: Теперь отправляет данные на `/api/auth/login/`
- **UserProfile.tsx**: Загружает и сохраняет данные профиля через API

#### 4. Обновленный main.tsx
- Добавлен `AuthProvider` для обеспечения контекста авторизации
- Упрощена конфигурация (удалены неиспользуемые tRPC провайдеры)

#### 5. Обновленный .env
- Добавлена переменная `VITE_API_URL=http://localhost:8000/api`

### Бэкенд (Django)

#### 1. Модели (`users/models.py`)
- **UserProfile**: Расширенный профиль пользователя с полями:
  - `level`: Уровень обучения (beginner, elementary, intermediate, advanced)
  - `study_streak`: Дневная серия обучения
  - `words_learned`: Количество выученных слов
  - `hours_studied`: Часов учебы
  - `daily_goal`: Ежедневная цель
  - `notifications_enabled`: Включены ли уведомления
  - `dark_theme`: Темная тема
  - `show_tips`: Показывать советы
  - `created_at`, `updated_at`: Даты создания и обновления

#### 2. Сериализаторы (`users/serializers.py`)
- **RegisterSerializer**: Валидация и создание новых пользователей
- **LoginSerializer**: Валидация данных входа
- **UserSerializer**: Сериализация информации о пользователе
- **UserProfileSerializer**: Сериализация профиля пользователя
- **UserDetailSerializer**: Полная информация о пользователе с профилем

#### 3. Представления (Views) (`users/views.py`)
- **AuthViewSet**: Управление аутентификацией
  - `register`: Регистрация нового пользователя
  - `login`: Вход пользователя
  - `logout`: Выход пользователя
  - `me`: Получение информации о текущем пользователе
  
- **UserProfileViewSet**: Управление профилем
  - `get_profile`: Получение профиля текущего пользователя
  - `update_profile`: Обновление данных профиля
  - `update_user_info`: Обновление информации о пользователе

#### 4. Конфигурация Django
- **settings.py**: Добавлены REST Framework, CORS, приложение users
- **urls.py**: Добавлены маршруты API
- **admin.py**: Регистрация моделей в админ-панели

## Как это работает

### Процесс регистрации

1. Пользователь заполняет форму на странице `/signup`
2. Фронтенд отправляет POST запрос на `/api/auth/register/`
3. Django проверяет данные и создает нового пользователя
4. Автоматически создается профиль пользователя
5. Фронтенд сохраняет информацию о пользователе в контексте
6. Пользователь перенаправляется на `/profile-setup`

### Процесс входа

1. Пользователь заполняет форму на странице `/login`
2. Фронтенд отправляет POST запрос на `/api/auth/login/`
3. Django проверяет учетные данные
4. Если верно, создается сессия и отправляется cookie
5. Фронтенд сохраняет информацию о пользователе в контексте
6. Пользователь перенаправляется на `/dashboard`

### Процесс обновления профиля

1. Пользователь редактирует данные на странице `/profile`
2. При нажатии "Сохранить" фронтенд отправляет PATCH запрос на `/api/profile/update_profile/`
3. Django обновляет данные в базе данных
4. Фронтенд обновляет локальное состояние
5. Данные сохраняются перманентно в базе данных

## Безопасность

### Аутентификация
- Используется **Session-based authentication** (встроенная в Django)
- Пароли хешируются с использованием PBKDF2 (по умолчанию в Django)
- Невозможно войти с рандомным паролем - проверяется хеш пароля

### CORS
- Настроены разрешенные источники для запросов
- Включена поддержка credentials (cookies)

### Валидация
- Все входные данные валидируются на сервере
- Email должен быть уникальным
- Пароль должен быть минимум 8 символов
- Пароли должны совпадать при регистрации

## Тестирование API

### Использование curl

```bash
# Регистрация
curl -X POST http://localhost:8000/api/auth/register/ \
  -H "Content-Type: application/json" \
  -d '{
    "email": "test@example.com",
    "username": "testuser",
    "password": "password123",
    "password_confirm": "password123"
  }'

# Вход
curl -X POST http://localhost:8000/api/auth/login/ \
  -H "Content-Type: application/json" \
  -c cookies.txt \
  -d '{
    "email": "test@example.com",
    "password": "password123"
  }'

# Получение профиля
curl -X GET http://localhost:8000/api/profile/get_profile/ \
  -b cookies.txt
```

### Использование Postman

1. Откройте Postman
2. Создайте новую коллекцию "SakuraLearn"
3. Добавьте запросы для каждого endpoint
4. Используйте вкладку "Cookies" для сохранения сессии между запросами

## Решение проблем

### Проблема: "CORS error"
**Решение**: Убедитесь, что:
- Бэкенд запущен на `http://localhost:8000`
- Фронтенд запущен на `http://localhost:5173` или `http://localhost:3000`
- В `.env` фронтенда установлена правильная `VITE_API_URL`

### Проблема: "Ошибка при входе - Пользователь с таким email не найден"
**Решение**: Убедитесь, что:
- Пользователь был зарегистрирован
- Используется правильный email
- База данных не была очищена

### Проблема: "Ошибка при сохранении профиля"
**Решение**: Убедитесь, что:
- Вы авторизованы (есть активная сессия)
- Отправляемые данные соответствуют формату API
- Бэкенд запущен и доступен
